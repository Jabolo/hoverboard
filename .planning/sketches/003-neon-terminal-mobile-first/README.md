# Sketch 003: Neon Terminal Mobile First

## Design Question

Can the Neon Terminal direction stay expressive and technical while making the mobile path to ticket selection and registration obvious, thumb-friendly, and low-friction?

## How to View

Open `.planning/sketches/003-neon-terminal-mobile-first/index.html` from the repository root or serve the repository with a local HTTP server so the official image assets resolve.

## Focused Direction

- **A: Neon Terminal** — stacked mobile-first hero, terminal status card, countdown, and visible ticket choices; the desktop layout expands into a two-column command-center composition.

## What to Look For

Pay attention to the order on a phone: event promise → primary CTA → event facts → status signal → ticket choices. The design intentionally treats the ticket catalogue as part of the landing story rather than a separate destination.

## Verification

- Reviewed at 412×915 (Pixel 7 emulation), 393×852 (iPhone 15 emulation), and desktop widths.
- Checked mobile horizontal overflow, 50px CTA tap targets, menu state, ticket selection, preview status, countdown, theme switcher, viewport controls, and annotation mode.
- Final browser pass: zero console errors, zero network errors, and a clean hidden-content prompt-injection scan.
